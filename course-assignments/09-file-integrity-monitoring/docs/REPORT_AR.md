# التقرير العملي — التكليف التاسع
## أداة مراقبة سلامة الملفات (File Integrity Monitoring — FIM)

**لغة البرمجة:** Python  
**الخوارزمية:** SHA-256  
**بيئة التنفيذ المستهدفة:** Windows PowerShell وبيئات Python 3.10+  
**الاعتماديات:** مكتبات Python القياسية فقط.

## 1. الهدف

إنشاء أداة دفاعية تراقب ملفاً محدداً للكشف عن التغييرات في محتواه. تنشئ الأداة بصمة مرجعية أولية (Baseline)، ثم تعيد حساب SHA-256 دورياً وتقارن البصمة الحالية بالقيمة المرجعية. عند وجود اختلاف، تطبع تنبيهاً حرجاً.

## 2. آلية العمل

1. يستقبل البرنامج مسار الملف من سطر الأوامر.
2. يفتح الملف بالوضع الثنائي rb ويقرأه على دفعات، افتراضياً 65,536 بايت لكل دفعة.
3. يحسب hashlib.sha256() البصمة التراكمية ويستخرجها باستخدام hexdigest().
4. عند أول تشغيل، يحفظ Baseline بتنسيق JSON تتضمن إصدار المخطط والخوارزمية والمسار المطلق والبصمة ووقت الإنشاء UTC.
5. في وضع التشغيل المستمر، ينفذ البرنامج حلقة while True، ويفحص الملف ثم يستدعي time.sleep() لمدة ثلاث ثوانٍ افتراضياً.
6. عند تطابق البصمتين، يطبع [OK].
7. عند اختلافهما، يطبع [ALERT] [CRITICAL] مع البصمة المرجعية والحالية.
8. إذا اختفى الملف، يطبع تنبيهاً حرجاً بأن الملف مفقود.

## 3. قرارات التنفيذ

### القراءة المجزأة
لا يقرأ البرنامج الملف كاملاً دفعة واحدة. يتم تمرير كل Chunk إلى كائن SHA-256 باستخدام update()، وهو ما يقلل استخدام الذاكرة ويتيح التعامل مع الملفات الكبيرة.

### حفظ Baseline
يُكتب ملف JSON مؤقت في مجلد Baseline نفسه ثم يُستبدل بالملف النهائي باستخدام os.replace() لتقليل احتمال ترك ملف مرجعي جزئي عند انقطاع الكتابة.

### عدم تحديث البصمة تلقائياً
عند اكتشاف تغيير، يحتفظ البرنامج بالبصمة المرجعية الأصلية ويستمر في المقارنة بها. تحديث Baseline يتطلب إجراءً صريحاً عبر --reset-baseline بعد التأكد من أن التغيير مشروع؛ وهذا يمنع إخفاء التعديلات غير المصرح بها بصورة صامتة.

### أوضاع التشغيل
- المراقبة المستمرة: الوضع الافتراضي.
- الفحص لمرة واحدة: --once لتسهيل التحقق والاختبارات.
- إعادة إنشاء Baseline: --reset-baseline بقرار صريح من المشغل.

## 4. التشغيل

تشغيل بالمعدل الافتراضي:

    python fim_tool.py samples/critical_config_sample.txt

تحديد فترة خمس ثوانٍ:

    python fim_tool.py samples/critical_config_sample.txt --interval 5

تحديد مسار Baseline:

    python fim_tool.py samples/critical_config_sample.txt --baseline fim_baseline.json

فحص واحد:

    python fim_tool.py samples/critical_config_sample.txt --once

## 5. التحقق العملي ونتائج Windows الفعلية

**تاريخ التحقق:** 12 نوفمبر 2026  
**نظام التشغيل:** Windows — PowerShell  
**إصدار Python:** 3.10.0

نفّذ الطالب الأوامر التالية في بيئته المحلية:

- عرض المساعدة باستخدام `python .\fim_tool.py --help` وظهور خيارات الأداة.
- فحص الصياغة باستخدام `python -m py_compile .\fim_tool.py .\tests\test_fim_tool.py` دون ظهور أخطاء.
- تشغيل اختبارات الوحدة باستخدام `python -m unittest discover -s .\tests -v`.

**نتيجة الاختبارات الفعلية:**

    Ran 14 tests in 0.144s

    OK

- الاختبارات الناجحة: 14.
- الاختبارات الفاشلة: 0.
- الاختبارات المتخطاة: 0.

**نتيجة العرض العملي للمراقبة المستمرة:**

1. أنشأت الأداة Baseline للنسخة المؤقتة من الملف.
2. أظهرت عدة دورات فحص سليمة برسالة `[OK] Integrity verified`.
3. بعد إضافة نص تجريبي إلى الملف، اكتشفت الأداة اختلاف البصمة وأظهرت `[ALERT] [CRITICAL] FILE INTEGRITY VIOLATION DETECTED!`.
4. أظهرت المقارنة بصمتين مختلفتين؛ المرجعية `02c0d3844bfe776cc3f7fc921d9a44f4136e05fbd127ebef34634b4b55e7f03e` والحالية `8796f1f91fa93d6f07d89e8c4b6eb3df613ae28165aa31de883ed71f6d54eb8b`.
5. حافظت الأداة على Baseline الأصلية وأبقت التنبيه ظاهراً عند استمرار الاختلاف.

استُخدمت نسخة مؤقتة في مجلد TEMP ولم يُعدّل ملف العينة الأصلي. تمثل النتائج أعلاه ما ظهر في سجل PowerShell المقدم من الطالب، أما لقطات الشاشة فتُحفظ منفصلة في مجلد `screenshots/`.

## 6. حدود الأداة والاعتبارات الأمنية

- SHA-256 تكشف اختلاف المحتوى، لكنها لا تحدد هوية من أجرى التعديل ولا تثبت أن التغيير خبيث.
- إذا تمكن المهاجم من تعديل الملف وملف Baseline معاً، فقد تتعرض المقارنة للتضليل. يجب حماية Baseline بصلاحيات صارمة أو وضعها خارج نطاق صلاحية المستخدم غير الموثوق.
- هذه النسخة تراقب ملفاً واحداً باستخدام Polling؛ لذلك يكون زمن الكشف مرتبطاً بفترة الفحص، وليس فورياً على مستوى أحداث نظام الملفات.
- قد تتأثر القراءة بتزامن الكتابة أو حذف الملف أو عدم توفر صلاحية القراءة. تسجل الأداة الخطأ ولا تفترض سلامة الملف.
- الأداة تعليمية ولا تغني عن أنظمة FIM المؤسسية أو إدارة الأحداث والتنبيهات المركزية.

## 7. الخلاصة

يطبق المشروع آلية مراقبة قائمة على SHA-256 وBaseline محفوظة، مع قراءة ثنائية مجزأة وفحص دوري وتنبيه حرج عند التغيير أو الاختفاء. تم فصل إنشاء Baseline عن تحديثها، بحيث لا يُقبل المحتوى الجديد تلقائياً بعد اكتشاف تعديل.
