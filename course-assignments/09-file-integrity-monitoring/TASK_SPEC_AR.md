# التكليف التاسع: أداة مراقبة سلامة الملفات
## File Integrity Monitoring (FIM)

**مسار البرمجة:** الأمن السيبراني — Python

## 1. الوصف العام

تطوير أداة دفاعية بلغة Python لمراقبة سلامة ملف حساس. تنشئ الأداة بصمة مرجعية أولية باستخدام SHA-256، ثم تعيد حساب البصمة بصورة دورية وتقارنها بالقيمة المحفوظة. عند اكتشاف اختلاف، تطبع تنبيهاً أمنياً حرجاً.

## 2. خطوات التنفيذ

1. كتابة دالة تقرأ محتوى الملف وتحسب SHA-256.
2. فتح الملف بالوضع الثنائي rb لتجنب تغيير البايتات أثناء القراءة.
3. قراءة الملفات على أجزاء (Chunks) بدلاً من تحميل الملف كاملاً إلى الذاكرة.
4. إنشاء Baseline أولية عند أول تشغيل وحفظ المسار والبصمة والخوارزمية ووقت الإنشاء.
5. إنشاء حلقة مراقبة مستمرة باستخدام while True.
6. استخدام time.sleep() للفصل بين عمليات الفحص، مع فترة افتراضية مقدارها 3 ثوانٍ.
7. مقارنة البصمة الحالية بالبصمة المرجعية المخزنة.
8. طباعة CRITICAL ALERT عند تعديل الملف، وكذلك التنبيه عند اختفاء الملف.
9. إيقاف المراقبة يدوياً باستخدام Ctrl+C دون إتلاف البصمة أو تحديثها تلقائياً.

## 3. معايير القبول

- حساب SHA-256 بصورة صحيحة لملف ثنائي أو نصي.
- إنشاء Baseline تلقائية في أول تشغيل.
- اكتشاف تعديل حرف واحد على الأقل خلال دورة الفحص التالية.
- استمرار حلقة المراقبة بشكل مستقر حتى إيقافها يدوياً.
- استخدام rb والقراءة المجزأة (Chunked Reading).
- استخدام time.sleep() لتقليل استهلاك المعالج.
- تقديم رسائل واضحة للحالة الطبيعية والتعديل والملف المفقود.
- عدم استبدال Baseline تلقائياً بعد اكتشاف التعديل.
- توثيق طريقة التشغيل والاختبارات وحدود الأداة.

## 4. ملفات المشروع

- fim_tool.py: التنفيذ وواجهة سطر الأوامر.
- tests/test_fim_tool.py: اختبارات الوحدة.
- samples/critical_config_sample.txt: ملف تجريبي غير حساس.
- docs/: التقرير ونتائج الاختبار ومصفوفة التتبع.
- screenshots/: لقطات التنفيذ الفعلية.

## 5. ملاحظة أمنية

البصمة المرجعية هي أساس الثقة في المقارنة. إذا استطاع مهاجم تعديل الملف والبصمة معاً، فقد لا تكتشف الأداة التلاعب. لذلك ينبغي حماية ملف Baseline بصلاحيات مناسبة أو حفظه في موقع موثوق منفصل في الأنظمة الحقيقية. هذا المشروع تعليمي ولا يُعد بديلاً عن حلول FIM المؤسسية.
