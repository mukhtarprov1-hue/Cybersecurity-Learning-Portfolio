# التقرير الفني — التكليف الثالث عشر
## أداة إدارة الجلسات والكوكيز المحمية (Session & Cookie Security)

**المسار:** البرمجة للأمن السيبراني — Web & PHP  
**بيئة التنفيذ المستهدفة:** PHP 8.2+  
**مبدأ التصميم:** Secure by Default · Defence in Depth

## 1. الملخص التنفيذي

ينفذ المشروع مختبراً تعليمياً لإدارة جلسات PHP والكوكيز. يضبط خصائص الجلسة قبل session_start()، ويصدر كوكي جلسة باسم CYBERSESSID بخصائص HttpOnly وSecure وSameSite=Strict. كما يصدر كوكيين تجريبيين للمقارنة: DEMO_SAFE محمي، وDEMO_UNSAFE غير محمي عمداً ويحمل قيمة تعليمية عامة غير سرية.

يوفر المشروع تدفق تسجيل دخول محاكياً يجدد معرف الجلسة عبر session_regenerate_id(true)، وينشئ رمز CSRF مرتبطاً بالجلسة، ويعرض لوحة محمية تستمر فيها حالة الجلسة، ثم ينهي الجلسة عند تسجيل الخروج.

> زر تسجيل الدخول يحاكي حدث المصادقة فقط، ولا يمثل نظام مصادقة حقيقياً أو قابلاً للنشر.

## 2. إعداد الجلسة

تُنفذ الإعدادات قبل session_start() باستخدام session_set_cookie_params() ومصفوفة الخيارات:

| الخاصية | القيمة | الغرض |
|---|---|---|
| httponly | true | منع JavaScript من قراءة الكوكي |
| secure | true افتراضياً | إرسال الكوكي عبر HTTPS فقط |
| samesite | Strict | تقليل إرسال الكوكي في طلبات cross-site |
| path | / | إتاحة الكوكي ضمن التطبيق |
| Session name | CYBERSESSID | اسم واضح لبيئة المختبر |

كما يفعّل التطبيق session.use_strict_mode=1 وsession.use_only_cookies=1 ويوقف session.use_trans_sid=0 لمنع تمرير Session ID في URL.

## 3. مقارنة الكوكيز

### الكوكي المحمي DEMO_SAFE

- HttpOnly=true
- Secure=true
- SameSite=Strict

لا يمكن لكود JavaScript قراءته من document.cookie بسبب HttpOnly، لكن المتصفح يرسله تلقائياً إلى الخادم وفق نطاقه وشروطه.

### الكوكي التعليمي غير المحمي DEMO_UNSAFE

- HttpOnly=false
- Secure=false
- SameSite=Lax

يحتوي قيمة عامة غير سرية حتى يمكن أن يظهر في document.cookie للمقارنة. لا يحمل Session ID أو بيانات اعتماد أو أسراراً حقيقية.

ملف public/assets/cookie-probe.js يقرأ document.cookie ويعرض الكوكيز المرئية.

## 4. Session Fixation

عند تنفيذ حدث الدخول التجريبي، ينفذ التطبيق session_regenerate_id(true) لحذف معرف الجلسة السابق من الخادم وإصدار معرف جديد. يتم التحقق من أن المعرف تغير بالفعل، وتخزن الجلسة حالة المصادقة بعد التجديد. يعرض التطبيق بصمة مختصرة مشتقة من SHA-256 بدلاً من كشف Session ID الخام.

## 5. CSRF وحماية الطلبات

تستخدم النماذج رمزاً عشوائياً بطول 256 بت (64 خانة hex) مرتبطاً بالجلسة. يتحقق التطبيق من الرمز باستخدام hash_equals() في عمليات POST. يجدد الرمز بعد الدخول، ويتطلبه عند تسجيل الخروج. تعمل هذه الطبقة مع SameSite Strict ولا تستبدلها.

## 6. الاختبارات

يتضمن المشروع مجموعتين:

- **15 اختبار سياسة/وحدة:** إعدادات HttpOnly وSecure وSameSite، أوضاع الجلسة الصارمة، خصائص CSRF، تدوير الرمز، تجديد Session ID، بصمة معرف الجلسة، ومقارنة خصائص الكوكيز.
- **11 اختبار HTTP تكاملي:** تشغيل خادم PHP محلي على Loopback، فحص Set-Cookie الفعلية، رفض POST دون CSRF (403)، تجديد Session ID عند الدخول، استمرار المصادقة في لوحة التحكم، إنهاء الجلسة عند الخروج، ورفض الوصول للوحة بعد الخروج.

**نتيجة بيئة البناء:** PHP 8.4.24، فحص الصياغة 8/8، اختبارات السياسة 15/15، واختبارات HTTP 11/11. هذه نتائج بيئة البناء وليست نتيجة جهاز الطالب. تبقى لقطات الشاشة والتحقق المحلي ضمن المرحلة اللاحقة حسب ترتيب تسليم التكليفات.

## 8. القيود وخطوات التطوير اللاحقة

- تسجيل الدخول في هذا المختبر محاكاة تعليمية وليس مصادقة بكلمة مرور.
- HttpOnly يمنع سرقة قيمة الكوكي مباشرة عبر document.cookie، لكنه لا يمنع XSS من تنفيذ طلبات مصادق عليها داخل المتصفح.
- SameSite Strict عامل دفاع إضافي وليس بديلاً عن CSRF tokens والتحقق من Origin/Referer والصلاحيات.
- Secure يتطلب HTTPS في بيئة الإنتاج.
- من التحسينات اللاحقة: مهلات idle/absolute للجلسة، MFA، إدارة إلغاء الجلسات مركزياً، مراقبة إعادة استخدام الجلسات، سياسة تدوير بعد رفع الصلاحيات، وتكامل مصادقة حقيقي.

## 9. الخلاصة

يوضح المشروع عملياً خصائص كوكيز الجلسة، الفرق بين HttpOnly وغيابه، أثر SameSite وSecure، وتجديد Session ID بعد حدث الدخول، مع اختبارات تقرأ ترويسات Set-Cookie الحقيقية وتتحقق من استمرار الجلسة وإنهائها.
