# التقرير الفني — التكليف الحادي عشر
## SQL Injection Defense باستخدام PHP PDO

**المسار:** برمجة الأمن السيبراني — Web & PHP  
**التقنية:** PHP + PDO + SQLite in-memory  
**حالة التحقق المحلي:** بانتظار تشغيل الاختبارات على جهاز Windows وإرفاق لقطات التنفيذ الأصلية.

## 1. الملخص التنفيذي

يهدف هذا التكليف إلى توضيح كيف يؤدي دمج إدخال المستخدم مباشرة داخل نص استعلام SQL إلى ثغرة حقن قواعد البيانات (SQL Injection)، وكيف تمنع المعاملات المجهزة (Prepared Statements) تفسير مدخل المستخدم على أنه جزء من كود SQL.

تم إعداد تطبيق ويب محلي بصفحة واحدة وقاعدة بيانات SQLite مؤقتة تُنشأ في الذاكرة عند كل طلب. يحتوي الجدول على سجلات اصطناعية فقط. يوفر التطبيق وضعين للمقارنة: وضعاً غير آمن مقصوداً للتجربة، ووضعاً آمناً يعتمد على PDO.

## 2. الهدف

- إنشاء اتصال قاعدة بيانات باستخدام PDO.
- إنشاء جدول مستخدمين وإدخال بيانات اختبار اصطناعية.
- تنفيذ البحث بطريقة غير آمنة بهدف مشاهدة أثر الحقن.
- تنفيذ البحث نفسه باستخدام `prepare()` و`execute()`.
- اختبار مدخل هجومي ومقارنة نتيجة الوضعين.
- تجنب تسريب أخطاء قاعدة البيانات أو تفاصيلها في واجهة المستخدم.

## 4. تهيئة قاعدة البيانات

تستخدم الأداة DSN التالي:

```php
new PDO('sqlite::memory:', null, null, [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);
```

بعد الاتصال يُنشأ جدول `users` بأعمدة: `id`, `username`, `email`, `role`. ثم تُضاف خمسة سجلات اختبارية باستخدام استعلام إدخال مجهز. لا تُنشأ ملفات قاعدة بيانات على القرص، وتُفقد البيانات المؤقتة بعد انتهاء الطلب.

## 5. توضيح الثغرة

في المسار غير الآمن يبنى الاستعلام من خلال دمج النص:

```php
$sql = "SELECT id, username, email, role
        FROM users
        WHERE username = '" . $username . "'
        ORDER BY id ASC";

$statement = $pdo->query($sql);
```

عند استخدام الحمولة:

```text
' OR '1'='1' --
```

تصبح البنية المنطقية للشرط في الاستعلام الناتج على نحو يقارب:

```sql
WHERE username = '' OR '1'='1' -- '
```

الشرط `'1'='1'` صحيح، وعلامة التعليق تجعل الجزء اللاحق من السطر غير مؤثر؛ لذلك قد يعيد الاستعلام جميع السجلات التجريبية بدلاً من سجل واحد مطابق.

## 6. المعالجة الآمنة

يقرأ التطبيق مدخل البحث من `$_GET['username']`، ثم يعتمد المسار الآمن على معامل مسمى:

```php
$statement = $pdo->prepare(
    'SELECT id, username, email, role
     FROM users
     WHERE username = :username
     ORDER BY id ASC'
);

$statement->bindValue(':username', $username, PDO::PARAM_STR);
$statement->execute();
```

هنا لا تُدمج قيمة المستخدم في نص SQL. تُرسل القيمة إلى المحرك باعتبارها بيانات مرتبطة بالمعامل `:username`. لذلك لا تتحول العلامات والعبارات الموجودة داخلها إلى عوامل SQL أو شروط إضافية.

## 7. خطة الاختبار

| الاختبار | النتيجة المتوقعة |
|---|---|
| البحث الآمن عن `alice` | سجل واحد مطابق |
| البحث الآمن بحمولة الحقن | صفر سجلات |
| البحث غير الآمن بحمولة الحقن | إظهار جميع سجلات المختبر الخمسة لإثبات الخطر |
| اسم مستخدم مشروع يحتوي فاصلة عليا `o'connor` | سجل واحد في الوضع الآمن |
| إعداد PDO للأخطاء | `PDO::ERRMODE_EXCEPTION` |
| أعمدة النتيجة | الأعمدة المسموح بعرضها فقط |

**تنبيه توثيقي:** الجدول أعلاه يصف نتائج الاختبار المتوقعة من الكود؛ لا يُسجل كدليل تنفيذ فعلي حتى تشغيل `php tests/run.php` محلياً وحفظ مخرجاته.

## 8. معالجة الأخطاء والإخراج

- يستخدم PDO نمط `ERRMODE_EXCEPTION` لتوحيد التعامل مع أخطاء الاستعلام.
- تكتب تفاصيل الاستثناء إلى سجل خادم PHP فقط، ولا تُطبع في صفحة الويب.
- تعرض الواجهة رسالة عامة لا تكشف أسماء الجداول أو نص الاستعلام أو تفاصيل الاتصال.
- تستخدم الدالة `htmlspecialchars()` لترميز القيم قبل إدراجها في HTML.
- تضع الصفحة حدوداً لطول المدخل وتستخدم رؤوساً أساسية لتقليل بعض مخاطر المتصفح.

## 11. حدود الحل

هذا مشروع تعليمي لا يطبق تسجيل دخول حقيقياً ولا يخزن كلمات مرور. البيانات اصطناعية ومؤقتة، والاتصال محلي. كما أن المثال يوضح منع حقن القيم النصية؛ أما أسماء الجداول والأعمدة أو اتجاه الفرز فلا تُحمى بربط المعاملات، ويجب اختيارها من قائمة مسموح بها عند الحاجة إلى جعلها ديناميكية. لا ينبغي اعتبار المثال نظاماً إنتاجياً مكتملاً.

## 12. الخلاصة

الفارق الأمني ليس في شكل الحمولة ولا في حذف بعض الرموز منها، بل في طريقة بناء الاستعلام. دمج مدخل غير موثوق داخل SQL يخلط البيانات بالتعليمات، بينما تفصل Prepared Statements بين قالب الاستعلام والقيم المرتبطة به. لذلك يُعد استخدام المعاملات المجهزة هو الأساس الصحيح لمعالجة هذه الفئة من حقن SQL.
