# التقرير الفني — التكليف الحادي عشر
## SQL Injection Defense باستخدام PHP PDO

**المسار:** برمجة الأمن السيبراني — Web & PHP  
**التقنية:** PHP 8.5.12 + PDO + SQLite in-memory  
**حالة التحقق المحلي:** **مكتمل — PASS** على Windows PowerShell.  
**نتيجة GitHub Actions:** **4/4 وظائف ناجحة** على Windows وUbuntu باستخدام PHP 8.2 و8.5.

## 1. الملخص التنفيذي

يشرح التكليف كيف يؤدي دمج مدخل المستخدم مباشرة داخل نص SQL إلى ثغرة حقن قواعد البيانات (SQL Injection)، وكيف تمنع المعاملات المجهزة (Prepared Statements) تفسير مدخل المستخدم على أنه جزء من كود SQL.

التطبيق صفحة PHP واحدة، مع قاعدة SQLite مؤقتة تُنشأ في الذاكرة عند كل طلب، وجدول يحتوي خمسة سجلات اصطناعية. يتيح وضعين للمقارنة: استعلاماً غير آمن متعمداً للتوضيح، واستعلاماً آمناً يستخدم PDO.

## 2. الأهداف

- إنشاء اتصال قاعدة بيانات باستخدام PDO.
- إنشاء جدول مستخدمين وإضافة بيانات اصطناعية.
- إظهار أثر الدمج النصي غير الآمن.
- معالجة البحث باستخدام `prepare()` و`bindValue()` و`execute()`.
- اختبار حمولة SQLi ومقارنة نتائج الوضعين.
- عدم تسريب تفاصيل الاستثناءات أو بنية قاعدة البيانات إلى المتصفح.

## 4. قاعدة البيانات

تُنشأ قاعدة البيانات باستخدام DSN:

~~~php
new PDO('sqlite::memory:', null, null, [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
]);
~~~

يُنشأ جدول `users` بالأعمدة `id` و`username` و`email` و`role`، ثم تضاف خمسة سجلات تجريبية باستخدام استعلام إدخال مجهز. لا تُنشأ قاعدة بيانات دائمة على القرص، وتُعاد تهيئة السجلات عند كل طلب.

## 5. توضيح الثغرة

المسار الضعيف يدمج مدخل المستخدم داخل الاستعلام ثم ينفذه باستخدام `PDO::query()`. عند إرسال الحمولة التالية:

~~~text
' OR '1'='1' -- 
~~~

يصبح شرط اسم المستخدم قابلاً للتجاوز، فتُعرض السجلات التجريبية الخمسة. هذا المسار موجود للتوضيح المحلي فقط ولا يجوز نشره أو ربطه ببيانات حقيقية.

## 6. المعالجة الآمنة

يستخدم المسار الآمن معامل SQL مسمى `:username`:

~~~php
$statement = $pdo->prepare(
    'SELECT id, username, email, role
     FROM users
     WHERE username = :username
     ORDER BY id ASC'
);

$statement->bindValue(':username', $username, PDO::PARAM_STR);
$statement->execute();
~~~

تُمرر قيمة المستخدم كبيانات منفصلة عن بنية SQL؛ لذلك تبقى حمولة الحقن قيمة نصية ولا تتحول إلى عامل أو شرط SQL.

## 9. معالجة الأخطاء والإخراج

- يستخدم PDO نمط `ERRMODE_EXCEPTION`.
- تُكتب تفاصيل الاستثناء إلى سجل خادم PHP ولا تُرسل إلى المتصفح.
- تُعرض رسالة عامة عند فشل التهيئة أو البحث.
- تُرمّز القيم التي تظهر داخل HTML باستخدام `htmlspecialchars()`.
- يوجد حد لطول المدخل، مع رؤوس استجابة مثل `X-Content-Type-Options` وسياسة CSP.
- قاعدة البيانات مؤقتة وتحوي سجلات اصطناعية فقط.

## 14. الخلاصة

الفارق الأمني ليس في حذف بعض الرموز من المدخل، بل في طريقة بناء الاستعلام. دمج المدخل غير الموثوق داخل SQL يخلط البيانات بالتعليمات، بينما تفصل Prepared Statements بين قالب الاستعلام والقيم المرتبطة به. لذلك فإن استخدام المعاملات المجهزة هو الضابط الأساسي لمعالجة هذا النوع من حقن SQL.
