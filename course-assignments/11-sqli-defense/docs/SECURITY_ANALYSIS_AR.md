# تحليل أمني: SQL Injection مقابل PDO Prepared Statements

## 1. أصل المشكلة

تحدث SQL Injection عندما تُعامل قيمة يتحكم بها المستخدم على أنها جزء من تعليمة SQL. الخلل هنا في بناء الاستعلام، وليس في كون القيمة تحتوي على علامة اقتباس بمفردها.

## 2. مقارنة التنفيذ

| البند | غير آمن | آمن |
|---|---|---|
| بناء الاستعلام | دمج قيمة المستخدم في السلسلة | قالب SQL بمعامل مسمى |
| طريقة التنفيذ | `PDO::query()` بعد تركيب النص | `PDO::prepare()` ثم `execute()` |
| تفسير حمولة الحقن | قد تغير منطق الشرط | تبقى قيمة نصية للمعامل |
| البحث الطبيعي | يعيد المطابقة | يعيد المطابقة |
| حمولة `' OR '1'='1' -- ` | قد تتجاوز شرط اسم المستخدم | لا تطابق اسماً حقيقياً |
| الاستخدام | محاكاة مختبرية فقط | النمط الموصى به لقيم SQL |

## 3. نموذج التهديد

**الأصل المحمي:** بيانات جدول المستخدمين، حتى وإن كانت هنا بيانات وهمية.  
**مدخل غير موثوق:** قيمة حقل username المرسلة من المتصفح.  
**سطح الهجوم:** استعلام البحث المبني في PHP.  
**الأثر المحتمل في تطبيق حقيقي:** تجاوز شروط البحث أو المصادقة، وقراءة بيانات غير مصرح بها، وقد يمتد الضرر إلى التعديل أو الحذف وفق صلاحيات الحساب وبنية الاستعلام.  
**الضابط الأساسي:** المعاملات المجهزة وربط القيمة كبيانات.

## 4. لماذا لا يكفي فلترة الرموز؟

قوائم الحظر أو محاولة حذف كلمات مثل `OR` أو علامات الاقتباس ليست بديلاً عن الفصل بين التعليمات والبيانات؛ يمكن أن تختلف طرق كتابة الحمولة أو ترميزها. يجب بناء الاستعلام بشكل صحيح واستخدام معاملات مربوطة.

## 5. ملاحظات PDO

- `PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION` يجعل الأخطاء قابلة للمعالجة عبر الاستثناءات.
- `bindValue(':username', $username, PDO::PARAM_STR)` يحدد القيمة باعتبارها نصاً.
- `execute()` ينفذ الاستعلام بعد ربط المعامل.
- لا يمكن عادة ربط اسم جدول أو عمود أو كلمة `ORDER BY` بمعامل قيمة؛ استخدم قائمة سماح ثابتة لهذه الأجزاء إذا احتجت إلى جعلها ديناميكية.
- يجب ألا تعرض رسائل الاستثناء أو تفاصيل البنية الداخلية للعميل.

## 6. ضوابط إضافية في المثال

1. قاعدة بيانات SQLite مؤقتة ببيانات اصطناعية.
2. حد أقصى لطول مدخل اسم المستخدم.
3. ترميز HTML للنتائج المعروضة.
4. رسالة خطأ عامة للمتصفح، مع إرسال التفاصيل إلى سجل الخادم فقط.
5. رؤوس استجابة أساسية مثل `X-Content-Type-Options` وسياسة CSP.

هذه الضوابط لا تحل محل Prepared Statements، بل تأتي كطبقات مساعدة. وأهم ضابط ضد حقن القيم في الاستعلامات هو عدم تركيب SQL بمدخلات غير موثوقة.

## 7. ما لا يغطيه المشروع

المشروع لا يمثل بوابة تسجيل دخول ولا نظام صلاحيات أو إدارة جلسات. لا يستخدم كلمات مرور ولا يثبت أمن نظام إنتاج كامل. كما أن SQLite in-memory هدفها سهولة المختبر، وقد تختلف التفاصيل التشغيلية بين محركات قواعد البيانات؛ لذلك يجب اختبار التطبيق الحقيقي على المحرك المستخدم فعلياً.
