# التقرير الفني — التكليف الرابع عشر
## أداة التفاعل مع DOM والوقاية من DOM-XSS

**المسار:** البرمجة للأمن السيبراني — Web & JavaScript  
**التقنيات:** HTML5 · CSS · Vanilla JavaScript · Playwright

## 1. الملخص التنفيذي

ينفذ المشروع مختبراً تفاعلياً يوضح خطورة استخدام innerHTML عند إدراج مدخلات غير موثوقة في DOM، ويقارن ذلك بالأسلوب الآمن textContent. يوفر المختبر حقل إدخال، وحمولا تعليمية، ومسارين منفصلين للعرض، وحالة مرئية لنتائج الاختبار.

## 2. المسار غير الآمن

تُستخدم الخاصية innerHTML في نقطة إدراج مقصودة لتوضيح أن المتصفح يعامل السلسلة كعلامات HTML. يمكن لبعض العناصر وسمات الأحداث أن تؤدي إلى تنفيذ JavaScript عند تحليلها. ولمنع تعريض الصفحة الأساسية للحمولة، يتم تنفيذ نقطة الإدراج التعليمية داخل iframe معزول يحمل sandbox="allow-scripts" دون allow-same-origin.

تسمح بيئة الإطار بصورة data محلية وبسكريبت الاختبار فقط، وتحظر اتصالات الشبكة الخارجية والنماذج والإطارات المتداخلة. ترسل الحمولة علامة DOM_XSS_PROOF ثابتة إلى الصفحة الأم، ويقبل التطبيق الرسالة فقط من نافذة iframe المحددة ذات الأصل المعتم null.

## 3. المسار الآمن

ينشئ التطبيق عنصر PRE باستخدام document.createElement('pre')، ويضع المدخل عبر textContent، ثم يضيف العنصر إلى الحاوية باستخدام appendChild(). بهذه الطريقة لا يعيد المتصفح تفسير الأحرف كوسوم HTML ولا ينفذ سمات الأحداث.

## 4. الحمولة التعليمية

تستخدم الحمولة الافتراضية عنصر IMG مع onerror يرسل رسالة إثبات محلية. لا تستدعي alert، ولا تقرأ document.cookie أو localStorage، ولا تنفذ طلباً خارجياً. الهدف إثبات مبدأ DOM-XSS بأقل أثر ممكن داخل إطار معزول.

## 5. اختبارات المتصفح

تستخدم المجموعة Playwright وChromium وتتحقق من:
- تحميل الصفحة ووجود حقل الإدخال وأزرار العرض.
- أن المسار الآمن يعرض الحمولة حرفياً ولا ينشئ IMG.
- أن معالج الحدث في المسار غير الآمن ينفذ داخل iframe المعزول فقط.
- بقاء نتيجة المسار الآمن مستقلة عند تشغيل المسار غير الآمن.
- عمل زر المسح وإعادة الضبط.
- عرض النص العادي وعلامات الاقتباس كبيانات نصية.
- عدم تسجيل pageerror في اختبار التنفيذ.

## 7. حدود المشروع

- هذا مختبر توضيحي وليس أداة لاكتشاف جميع أنواع XSS.
- sandbox/CSP عزل إضافي للحمولة التعليمية؛ لا يبرران استخدام innerHTML مع بيانات غير موثوقة.
- عند الحاجة إلى إدراج HTML من مصدر غير موثوق في تطبيق حقيقي، يجب استخدام Sanitizer موثوق وقائمة سماح صارمة، مع تفضيل textContent للنصوص.
- نتائج CI ولقطات جهاز الطالب أمران منفصلان. ستضاف صور المتصفح الأصلية في المرحلة المحلية اللاحقة، ولا تدعي هذه الوثيقة أنها التقطت بالفعل.
