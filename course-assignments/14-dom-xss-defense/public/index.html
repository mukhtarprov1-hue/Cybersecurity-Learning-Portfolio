مختبر التفاعل مع DOM والوقاية من DOM-XSS

قارن بين إدراج HTML غير الموثوق عبر innerHTML ومعالجته كنص عبر textContent، وشاهد إثباتاً تعليمياً معزولاً للتنفيذ.

Assignment 14 Client-side JavaScript Safe-by-default output
01

مدخل المستخدم

استخدم الحمولة التعليمية المقترحة أو أدخل نصاً تجريبياً خاصاً بك.

الحمولة الافتراضية ترسل علامة إثبات فقط إلى الصفحة الأم؛ لا تعرض نافذة منبثقة ولا تحاول قراءة الكوكيز.

02A

المسار غير الآمن

element.innerHTML = userInput

Unsafe sink — معزول عمداً

يتم إدراج الحمولة باستخدام innerHTML داخل iframe ذي أصل فريد وsandbox يسمح بالسكريبت فقط، مع CSP تمنع اتصالات الشبكة. لا يستطيع الإطار قراءة DOM الصفحة الأم أو كوكيزها.

لم يتم تشغيل الحمولة بعد.

الإثبات المتوقع: تنفيذ معالج الحدث داخل الإطار وإرسال رسالة DOM_XSS_PROOF فقط. لا تُنفّذ الحمولة في DOM الصفحة الرئيسية.

02B

المسار الآمن

element.textContent = userInput

Safe sink — نص فقط

يتم إنشاء عنصر باستخدام createElement، وإسناد المدخل إلى textContent، ثم إضافته باستخدام appendChild. لا يتم تفسير HTML أو تنفيذ JavaScript.

لم يتم تشغيل العرض الآمن بعد.

سيظهر مدخل المستخدم هنا كنص حرفي.

النتيجة المتوقعة: ظهور علامات HTML والسمات كنص عادي دون إنشاء عناصر أو تشغيل أحداث.

03

التحقق الأمني المباشر

المختبر يعرض حالة كل نتيجة على حدة، ولا يعتمد على شكل الصفحة وحده.

✓الناتج الآمن يبقي المدخل نصاً ولا ينشئ عناصر HTML من الحمولة.
✓الاختبار غير الآمن معزول داخل iframe sandbox دون allow-same-origin.
✓يُحظر تحميل الصور من الشبكة داخل الإطار، وتُسمح صورة data محلية فقط لأغراض الاختبار.
✓لا توجد حمولة تقرأ cookies أو localStorage أو ترسل بيانات إلى خادم خارجي.
جاهز للاختبار — اختر أحد مساري العرض.

المبدأ الأمني

// Unsafe: parses attacker-controlled markup
target.innerHTML = untrustedInput;

// Safe: creates a text node, not executable markup
const output = document.createElement('pre');
output.textContent = untrustedInput;
safeContainer.appendChild(output);

ملاحظة: innerHTML ليس خطيراً بذاته عند التعامل مع HTML موثوق ومُعقّم بشكل صحيح؛ الخطر هو إدراج بيانات غير موثوقة دون ترميز أو تعقيم مناسب. الأفضل للنصوص العادية استخدام textContent.

مختبر تعليمي معزول — لا تستخدم مدخلات حساسة. يوضح هذا المشروع نوعاً محدداً من DOM-XSS ولا يمثل بديلاً عن مراجعة أمنية شاملة.
