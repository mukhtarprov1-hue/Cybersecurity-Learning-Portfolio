# التكليف الرابع عشر: أداة التفاعل مع DOM والوقاية من DOM-XSS

**المسار:** البرمجة للأمن السيبراني — Web & JavaScript

## الوصف العام

بناء تطبيق ويب تفاعلي باستخدام HTML وJavaScript يوضح مخاطر إدراج مدخلات المستخدم غير الموثوقة في DOM باستخدام innerHTML، ومقارنتها بالطريقة الآمنة textContent لتفادي DOM-based XSS.

## المتطلبات الأساسية

1. إنشاء واجهة HTML تحتوي حقل إدخال وزرين للعرض غير الآمن والآمن.
2. قراءة قيمة المدخل عبر document.getElementById(...).value.
3. توضيح خطورة innerHTML عند تمرير HTML غير موثوق.
4. استخدام textContent لعرض القيمة كنص حرفي.
5. استخدام document.createElement() وappendChild() لبناء عناصر DOM بطريقة آمنة.
6. اختبار حمولة تعليمية مثل عنصر img مع onerror وملاحظة الفرق بين المسارين.
7. التأكد من عدم ظهور أخطاء JavaScript غير متوقعة.

## معايير القبول

- إثبات قابلية تنفيذ event handler عند استخدام innerHTML.
- عرض الحمولة كنص عادي وعدم تنفيذها عند استخدام textContent.
- استقرار واجهة المختبر وعدم ظهور أخطاء Console.

## قرار العزل الأمني

يحدث إثبات innerHTML داخل iframe يحمل sandbox="allow-scripts" فقط، دون allow-same-origin. بذلك يكون الإطار ذا أصل فريد ولا يستطيع قراءة DOM الصفحة الأم أو كوكيزها. ويقيد CSP داخل الإطار الصور إلى data: ويمنع اتصالات الشبكة. حمولة الاختبار ترسل علامة ثابتة إلى الصفحة الأم لإثبات التنفيذ؛ ولا تستخدم alert أو قراءة الكوكيز أو إرسال البيانات للخارج.

المسار الآمن يستخدم createElement وtextContent وappendChild، لذلك يعرض المدخل حرفياً دون تحويله إلى عناصر HTML.
