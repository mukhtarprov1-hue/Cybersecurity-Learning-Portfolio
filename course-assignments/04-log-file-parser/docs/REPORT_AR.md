# التقرير الفني — التكليف الرابع
## أداة تحليل وتصفية السجلات الأمنية (Log File Parser)

**المسار التدريبي:** معسكر الأمن السيبراني 2026  
**رقم التكليف:** 04  
**لغة البرمجة:** C17  
**نوع التطبيق:** Command-Line Interface (CLI)  
**إعداد:** Mukhtar Alawady

## 1. الملخص التنفيذي

تم تطوير برنامج بلغة C لقراءة ملفات السجلات النصية والبحث عن كلمة مفتاحية يحددها المستخدم. عند العثور على الكلمة، يطبع البرنامج رقم السطر ومحتواه، ثم يعرض مجموع السطور المطابقة في ملخص نهائي. يعتمد التنفيذ على الدوال التي حددها التكليف: `fopen()` و`fgets()` و`strstr()`، مع التحقق من أخطاء فتح الملف وقراءته وإغلاقه.

## 2. هدف التكليف

محاكاة خطوة أولية من عمل محلل مركز العمليات الأمنية (SOC): تصفية سجل نصي بحثاً عن مؤشرات محددة مثل فشل تسجيل الدخول (`FAILED`) أو استجابة HTTP من نوع `404`. يساعد ذلك على تحديد الأسطر التي تستحق مراجعة بشرية لاحقة.

## 3. طريقة الاستخدام

```text
log_parser <log_file> <keyword>
```

مثالان:

```bash
./log_parser samples/sample.log FAILED
./log_parser samples/sample.log 404
```

اختيار الكلمة من وسيطات سطر الأوامر يسمح بإعادة استخدام البرنامج دون إعادة تجميعه لكل كلمة. البحث حرفي وحساس لحالة الأحرف.

## 4. تصميم التنفيذ

1. التحقق من وجود وسيطين: مسار الملف والكلمة المفتاحية، ورفض الكلمة الفارغة.
2. فتح الملف باستخدام `fopen(path, "r")`.
3. قراءة أجزاء الملف باستخدام `fgets()` ومخزن مؤقت حجمه 512 بايتاً.
4. تجميع أجزاء السطر الطويل في مخزن ديناميكي حتى الوصول إلى نهاية السطر `\n` أو نهاية الملف.
5. زيادة رقم السطر مرة واحدة لكل سطر منطقي، ثم استخدام `strstr()` للبحث عن الكلمة.
6. عند وجود تطابق، طباعة رقم السطر ومحتواه وزيادة عداد التنبيهات مرة واحدة.
7. معالجة السطر الأخير حتى إن لم ينته بمحرف سطر جديد، ثم فحص `ferror()` وإغلاق الملف باستخدام `fclose()`.
8. طباعة `Total alerts` بعدد السطور المطابقة.

## 5. لماذا جُمّعت الأجزاء إلى سطر منطقي؟

استخدام `fgets()` مع مخزن 512 بايتاً لا يعني أن كل استدعاء يمثل سطراً كاملاً؛ فقد يكون السطر الواحد أطول من 511 حرفاً. لو عُدّ كل استدعاء على أنه سطر مستقل، فستصبح أرقام الأسطر غير صحيحة، وقد تضيع مطابقة كلمة تقع عند حد جزأين.

لذلك يقرأ البرنامج كتل الإدخال في مخزن ثابت حجمه 512 بايتاً، ثم يجمع أجزاء السطر الحالي في ذاكرة قابلة للتوسعة. لا يحتفظ البرنامج بكل الملف أو بكل التنبيهات، بل يعيد استخدام مخزن السطر بعد فحصه.

**استهلاك الذاكرة:** يتناسب مع طول أطول سطر منفرد في الملف، وليس مع الحجم الكلي لملف السجل. وبذلك يمكن قراءة ملف يحتوي ملايين السطور القصيرة دون تحميلها كلها إلى الذاكرة. أما السطر الواحد غير المعتاد ذي الحجم الضخم فقد يحتاج إلى مساحة مماثلة لطوله.

## 6. العينة والنتائج المتوقعة

العينة التي ينشئها `samples/create_sample.py` اصطناعية وتتكون من ستة أسطر. تتضمن سطرين يحتويان `FAILED` وسطراً واحداً يحتوي `404`.

- عند البحث عن `FAILED`: المتوقع استخراج السطرين 2 و5، والإجمالي 2.
- عند البحث عن `404`: المتوقع استخراج السطر 4، والإجمالي 1.

سجلات التشغيل المحفوظة في `evidence/` تسجل المخرجات المرصودة. لا تحتوي العينة على سجلات مستخدمين حقيقية أو عناوين من بيئة تشغيل فعلية.

## 7. خطة التحقق

تغطي مجموعة الاختبارات عشر حالات:

| ID | الحالة | النتيجة المطلوبة |
|---|---|---|
| T-01 | استخراج `FAILED` | إظهار السطرين الصحيحين والأرقام والإجمالي 2 |
| T-02 | استخراج `404` | إظهار السطر المطابق والإجمالي 1 |
| T-03 | اختلاف حالة الأحرف | عدم مطابقة `failed` عند البحث عن `FAILED` |
| T-04 | تكرار الكلمة داخل السطر نفسه | احتساب السطر مرة واحدة لا عدد مرات ظهور الكلمة |
| T-05 | لا توجد مطابقات | إظهار رسالة مناسبة والإجمالي 0 |
| T-06 | ملف فارغ | نجاح القراءة والإجمالي 0 |
| T-07 | ملف غير موجود | رسالة خطأ وخروج غير صفري |
| T-08 | وسيطات ناقصة أو كلمة فارغة | عرض الاستخدام وخروج غير صفري |
| T-09 | سطر أطول من مخزن الإدخال وكلمة تعبر حد كتلتين | الحفاظ على رقم السطر ومطابقة الكلمة مرة واحدة |
| T-10 | ملف كبير من 6000 سطر | الحفاظ على رقم السطر 4321 والإجمالي 1 |

## 8. بيئة التنفيذ وإعادة الإنتاج

تم إعداد الحزمة لتُبنى بمعيار C17 مع تحذيرات GCC الصارمة:

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror -O2 log_parser.c -o log_parser
python3 samples/create_sample.py
./log_parser samples/sample.log FAILED
./log_parser samples/sample.log 404
python3 tests/run_tests.py ./log_parser
```

Python مطلوب لتوليد العينة وتشغيل اختبارات التكامل فقط؛ البرنامج التنفيذي يعتمد على مكتبة C القياسية.

## 9. حدود الحل وملاحظات أمنية

- `strstr()` تنفذ مطابقة نصية حرفية وحساسة لحالة الأحرف، ولا تنفذ تعبيرات نمطية أو تحليلاً سياقياً.
- الأداة لا تربط الأحداث عبر عدة مصادر، ولا تحسب خطورة الحادث، ولا تثبت أن السطر خبيث؛ إنها أداة تصفية أولية فقط.
- صُممت لملفات السجلات النصية. البايتات الصفرية المضمنة (NUL) لا تتوافق مع افتراضات دوال السلاسل النصية المستخدمة.
- لا تعدّل الأداة ملف السجل، وتفتح الملف للقراءة فقط.
- يجب عدم نشر سجلات حقيقية تتضمن أسماء مستخدمين أو عناوين داخلية أو رموز جلسات أو بيانات حساسة. استخدم عينات اصطناعية عند مشاركة الأدلة.

## 10. الخلاصة

ينفذ البرنامج مسار التكليف الأساسي: فتح ملف نصي، وقراءته بواسطة `fgets()`، والبحث بواسطة `strstr()`، واستخراج السطور المطابقة مع أرقامها، ثم إظهار إجمالي التنبيهات. كما يعالج السطور الطويلة دون تقسيمها منطقياً، ويعيد استخدام مخزن السطر بدلاً من الاحتفاظ بملف السجل بالكامل في الذاكرة.
