# التقرير العملي — التكليف الخامس

## أداة فحص المنافذ متعددة الخيوط (Multithreaded Port Scanner)

**المسار:** البرمجة للأمن السيبراني — Python  
**نوع الفحص:** TCP Connect Scan

## 1. مقدمة

يهدف المشروع إلى تطوير برنامج Python لفحص منافذ TCP لعنوان IPv4 محدد. يعتمد على مكتبة \`socket\` لمحاولة الاتصال بالمنافذ، وعلى \`concurrent.futures.ThreadPoolExecutor\` لتنفيذ مهام الفحص بالتوازي، ثم يعرض المنافذ المفتوحة عند اكتمال اكتشافها وملخصاً للحالات وزمن التنفيذ.

## 2. المتطلبات التي ينفذها الحل

- استقبال عنوان IPv4 مستهدف والتحقق من صحته.
- استقبال رقم المنفذ داخل دالة الفحص.
- استخدام \`settimeout()\` لمنع الانتظار غير المحدود.
- فحص المنافذ 1–1024 افتراضياً.
- استخدام 50 عاملاً افتراضياً عبر \`ThreadPoolExecutor\`.
- استخدام \`connect_ex()\`؛ القيمة \`0\` تعني نجاح اتصال TCP.
- طباعة المنافذ المفتوحة فور اكتمال مهامها.
- حساب زمن الفحص وإغلاق كل مقبس.

## 3. تصميم البرنامج

### 3.1 التحقق من الهدف

تستخدم \`validate_ipv4()\` مكتبة \`ipaddress\` لتطبيع عنوان IPv4 ورفض العناوين غير الصحيحة أو عناوين IPv6 في هذا الإصدار.

### 3.2 فحص منفذ واحد

تُنشأ وصلة TCP باستخدام:

\`\`\`python
socket.socket(socket.AF_INET, socket.SOCK_STREAM)
\`\`\`

ثم تضبط مهلة الاتصال ويستدعى \`connect_ex((target_ip, port))\`. عند إرجاع \`0\` يصنف المنفذ \`OPEN\`. إذا أعاد Windows رمزاً مثل \`WSAEWOULDBLOCK (10035)\` فهذا قد يعني أن الاتصال ما زال قيد التنفيذ؛ ينتظر البرنامج باستخدام \`select()\` ثم يقرأ \`SO_ERROR\` لمعرفة النتيجة النهائية. الرفض الصريح مثل \`WSAECONNREFUSED (10061)\` يصنف \`CLOSED\`.

### 3.3 التنفيذ المتوازي

تستخدم \`scan_ports()\` كائن \`ThreadPoolExecutor\` بعدد 50 عاملاً افتراضياً. وتستخدم \`as_completed()\` لإرجاع النتائج فور انتهاء كل مهمة، بدلاً من الالتزام بترتيب أرقام المنافذ.

### 3.4 الموارد والزمن

يستخدم البرنامج مدير سياق \`with socket.socket(...)\` لضمان إغلاق المقبس بعد كل محاولة، كما يقيس الزمن باستخدام \`time.perf_counter()\`.

## 4. تفسير الحالات

| الحالة | معناها |
|---|---|
| \`OPEN\` | قبل الطرف المستهدف اتصال TCP وقت الفحص. |
| \`CLOSED\` | أبلغ نظام التشغيل صراحةً أن الاتصال مرفوض. |
| \`TIMEOUT\` | لم يصل رد نهائي خلال المهلة؛ ولا يثبت ذلك أن المنفذ مغلق. |
| \`UNREACHABLE\` | أبلغ نظام التشغيل عن تعذر الوصول إلى المضيف أو الشبكة. |
| \`BLOCKED\` | منع نظام التشغيل أو سياسة أمنية محلية محاولة الاتصال. لا يثبت ذلك أن المنفذ مغلق. |
| \`ERROR\` | خطأ آخر غير مصنف أثناء إنشاء المقبس أو الاتصال. |

## 5. الاختبارات

يحتوي \`tests/test_port_scanner.py\` على 11 اختباراً، تشمل:

1. اكتشاف منفذ محلي مفتوح عبر مستمع TCP مؤقت.
2. محاولة اكتشاف منفذ محلي مربوط لكنه لا يستمع.
3. الانتظار الصحيح لاتصال Windows غير المتزامن الذي يكتمل مفتوحاً.
4. تصنيف اتصال Windows المعلّق الذي انتهى برفض الاتصال.
5. التعامل مع المهلة.
6. التحقق من IPv4 ورفض IPv6 والمدخل غير الصحيح.
7. تصنيف رفض الاتصال على POSIX وWindows.
8. تصنيف رموز Winsock للمهلة وتعذر الوصول والمنع.
9. التأكد من عدم انهيار البرنامج عند فشل إنشاء المقبس.

قد يتجاوز اختبار المنفذ المغلق نفسه (\`skipped\`) إذا كان Windows أو برنامج الحماية يسقط اتصالات Loopback بصمت ويعيد \`TIMEOUT\` أو \`BLOCKED\`. هذا تجاوز بيئي موضح، وليس نجاحاً زائفاً أو دليلاً على أن المنفذ مغلق. يوجد اختبار محاكى مستقل للتحقق من أن الرفض الصريح \`10061\` ينتج \`CLOSED\`.

## 6. النتائج المسجلة

### 6.1 التحقق في بيئة إعداد المشروع

- Python: \`3.13.5\`.
- \`py_compile\`: اكتمل دون أخطاء.
- اختبارات الوحدة: \`11/11 PASS\` في بيئة إعداد المشروع.

هذه نتيجة بيئة إعداد المشروع، وليست بديلاً عن نتائج Windows المسجلة أدناه.

### 6.2 نتائج التنفيذ الفعلية التي أرسلها الطالب من Windows (11 نوفمبر 2026)

**بيئة الاختبار:** Windows PowerShell، والهدف \`127.0.0.1\` (Loopback).

#### أ. التحقق من خدمة Simple TCP/IP Services

أظهر الأمر \`Get-Service -Name simptcp\`:

- الاسم: \`simptcp\`
- الاسم المعروض: \`Simple TCP/IP Services\`
- الحالة: \`Running\`

وأظهر \`Get-NetTCPConnection -State Listen\` أن العملية ذات PID \`19356\` تستمع على المنافذ TCP التالية: \`7\`, \`9\`, \`13\`, \`17\`, \`19\`، على عنواني الاستماع العامين \`0.0.0.0\` (IPv4) و\`::\` (IPv6).

#### ب. الفحص المحدود للمنافذ 7–19

الأمر:

\`\`\`powershell
python port_scanner.py 127.0.0.1 --start-port 7 --end-port 19 --workers 50 --timeout 1 --show-closed
\`\`\`

النتيجة المرصودة:

| المؤشر | النتيجة |
|---|---:|
| Ports checked | 13 / 13 |
| Open | 5 |
| Closed | 0 |
| Timed out | 8 |
| Unreachable | 0 |
| Blocked | 0 |
| Errors | 0 |
| Elapsed time | 2.014 seconds |

المنافذ التي أعلن البرنامج أنها مفتوحة كانت \`7\`, \`9\`, \`13\`, \`17\`, \`19\`. وتتطابق هذه المنافذ مع مستمعات خدمة \`Simple TCP/IP Services\` التي أظهرها Windows في الاستعلام السابق.

#### ج. الفحص الكامل للمنافذ 1–1024

الأمر:

\`\`\`powershell
python port_scanner.py 127.0.0.1 --start-port 1 --end-port 1024 --workers 50 --timeout 0.5
\`\`\`

الملخص الذي أرسله الطالب:

| المؤشر | النتيجة |
|---|---:|
| Ports checked | 1024 / 1024 |
| Open | 12 |
| Closed | 0 |
| Timed out | 1011 |
| Unreachable | 0 |
| Blocked | 1 |
| Errors | 0 |
| Elapsed time | 21.572 seconds |

هذه الأرقام هي مخرجات الجهاز وقت الاختبار، وليست نتيجة عامة ثابتة. لا يمكن استنتاج أن المنافذ الـ1011 مغلقة؛ فقد انتهت مهلة الاتصال، كما أن المنفذ المصنف \`BLOCKED\` لا يثبت أن المنفذ مغلق.

#### د. فحص بناء Python واختبارات الوحدة على Windows

الأمر:

\`\`\`powershell
python -m py_compile port_scanner.py tests/test_port_scanner.py
python -m unittest discover -s tests -v
\`\`\`

النتيجة:

- \`py_compile\`: اكتمل دون أخطاء.
- عدد الاختبارات: 11.
- الناجحة: 10.
- المتخطاة: 1.
- الفاشلة: 0.
- المخرج النهائي: \`OK (skipped=1)\`.

سبب تخطي \`test_detects_closed_local_tcp_port\` هو أن Windows أعاد \`TIMEOUT\` في اتصال Loopback بدلاً من رفض صريح؛ لذلك تخطى الاختبار هذه الحالة البيئية، ولم يزعم أن المنفذ مغلق. أما الاختبار المنفصل \`test_connect_ex_refused_result_is_closed\` فقد نجح، وهو يتحقق من تصنيف رمز رفض Windows \`10061\` إلى \`CLOSED\`.

### 6.3 ملخص حالة التحقق

- تم تنفيذ البرنامج على Windows على نطاق 1–1024.
- تم التحقق من خمسة منافذ مفتوحة على الأقل وربطها بخدمة Windows معروفة في الجهاز.
- اكتمل الفحص الكامل دون أخطاء عامة (\`Errors = 0\`).
- اجتاز بناء Python واختباراته على Windows: 10 ناجحة وواحد متخطّى بسبب تصفية Loopback.
- لا تعد حالات \`TIMEOUT\` أو \`BLOCKED\` دليلاً على أن المنفذ مغلق.

## 8. حدود الحل والسلامة

- يفحص TCP فقط ولا يفحص UDP.
- لا يحدد أسماء الخدمات أو إصداراتها أو إصدارات أنظمة التشغيل؛ المنفذ المفتوح يعني فقط أن اتصال TCP قُبل وقت الفحص.
- تتأثر النتائج بجدار الحماية والتوجيه وفقدان الحزم وسياسات الحماية ومهلة الاتصال.
- لا يجوز تحويل \`TIMEOUT\` أو \`BLOCKED\` أو \`UNREACHABLE\` إلى \`CLOSED\` دون دليل رفض صريح.
- لا تستخدم الأداة إلا على أجهزة تملكها أو مختبرات مصرح بها أو أهداف لديك تصريح واضح بفحصها.

## 9. الخلاصة

يطبق المشروع عناصر التكليف الأساسية باستخدام \`socket\` و\`connect_ex()\` و\`ThreadPoolExecutor\` مع مهلة اتصال وإغلاق للمقابس وعرض للمنافذ المفتوحة وقياس زمن التنفيذ. وتمت إضافة معالجة واضحة لرموز Winsock واختبارات تفصل النتائج الصريحة عن حالات الحظر أو عدم الاستجابة. وقد جرى تنفيذ الفحص واختبار الوحدات على Windows وتوثيق النتائج الفعلية أعلاه.
