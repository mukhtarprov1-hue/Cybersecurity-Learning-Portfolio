# حالة التكليف 10 — المتطلبات الأساسية والتطويرات اللاحقة

## الخلاصة

**المطلوب الأساسي من المدرب جاهز ومتحقق منه.** توجد إضافة تقنية لاحقة لسلسلة تدقيق HMAC داخل الفرع، ويجب التعامل معها كتطوير اختياري قيد الاستكمال، لا كشرط لقبول التكليف الأساسي.

لم تُحذف أي ملفات أو أكواد تخص هذا التطوير. بقيت كما هي حتى يمكن استكمالها لاحقًا.

## أ. المتطلبات الأساسية للتكليف — مكتملة

| المطلوب الأساسي | موضع التنفيذ | نتيجة التحقق المسجلة |
|---|---|---|
| التعامل مع طلبات HTTP وقراءة Method | `public/index.php` و`ApiApplication.php` | اجتياز اختبارات API |
| قراءة الترويسات وبيانات Authorization | `getallheaders()` مع fallback | اختبارات Bearer Token |
| قراءة جسم الطلب من `php://input` | `public/index.php` | اختبارات JSON |
| تحليل JSON والتحقق من صحته | `ApiApplication.php` | malformed JSON = 400 |
| التمييز بين GET وPOST وPUT وDELETE | مسارات CRUD | اختبارات CRUD |
| إرجاع JSON وحالات HTTP المناسبة | `ApiResponse.php` | 200 / 201 / 204 وغيرها |
| التعامل مع Bearer Token في عمليات التغيير | `hash_equals()` | missing/invalid token tests |
| التحقق من المدخلات وحجم الطلب | allow-list و64 KiB limit | 400/413/415/422 tests |

### سجل التحقق المحلي للمتطلبات الأساسية

- PHP 8.5.12 على Windows.
- فحص تركيب ملفات PHP: **9/9** دون أخطاء.
- اختبارات API الأساسية: **23/23** ناجحة.
- GET Health: HTTP 200.
- GET Collection: HTTP 200.
- POST Create: HTTP 201.
- GET Resource: HTTP 200.
- PUT Update: HTTP 200.
- DELETE Resource: HTTP 204.
- الخادم كان مربوطًا بعنوان loopback المحلي `127.0.0.1`.

التفاصيل موجودة في `docs/TEST_RESULTS.md` و`docs/REPORT_AR.md`. هذه النتائج تخص المتطلبات الأساسية، ولا تعني أن تطوير HMAC اللاحق اكتمل محليًا.

## ب. تطوير لاحق اختياري — HMAC-Chained Audit Trail

**الحالة: غير مكتمل محليًا / قيد التطوير.**

أُضيف هذا التطوير بعد تنفيذ المطلوب الأساسي، ويشمل:

- `src/AuditChain.php`
- `src/AuditLogger.php`
- `tools/audit_verify.php`
- `tests/audit_integrity.php`
- `scripts/load-audit-key.ps1`
- `docs/AUDIT_CHAIN_FORMAT.md`

الغرض منه ربط أحداث سجل التدقيق باستخدام HMAC-SHA256، والتحقق من تعديل السجلات أو إعادة ترتيبها أو حذف سجل داخلي.

### ما الذي تحقق منه؟

- اختبارات السلسلة التسعة موجودة.
- GitHub Actions اجتاز مصفوفة Windows/Ubuntu وPHP 8.2/8.5، بما فيها اختبارات التكامل الخاصة بالسلسلة.
- هذا نجاح CI فقط، ولا يساوي إكمال تحقق التطوير على جهاز الطالب.

### ما الذي لا يزال مطلوبًا قبل اعتبار التطوير مكتملًا؟

1. تحميل مفتاح HMAC محليًا من الملف الخارجي عبر `scripts/load-audit-key.ps1`.
2. تشغيل API وإنتاج أحداث في `storage/audit-chain.jsonl`.
3. تشغيل `php tests/audit_integrity.php` على جهاز Windows وتوثيق النتيجة الفعلية.
4. تشغيل `php tools/audit_verify.php` والتحقق من السلسلة الناتجة.
5. توثيق حدود التطوير وعدم وصفه بأنه tamper-proof.

**هذا التطوير غير مطلوب لاعتبار REST API الأساسي منجزًا.** لا تحذف ملفاته أو سجلاته بسبب كونه غير مكتمل.

## ج. ملفات التشغيل المحلية

الملفات التالية ناتجة عن تشغيل التطوير وليست مصدرًا برمجيًا مطلوبًا للتسليم:

- `storage/audit-chain.jsonl`
- `storage/audit-chain.jsonl.lock`

تُستثنى هذه الملفات من Git في `.gitignore` الخاص بفرع التكليف 10. احتفظ بها محليًا عند الحاجة إلى مواصلة الاختبار، ولا ترفعها إلى المستودع؛ فقد تتضمن بيانات وصفية عن طلبات التشغيل.

ملف مفتاح HMAC محفوظ خارج المستودع في ملف المستخدم `.assignment10-audit-hmac.key`. لا ترفعه أو تضع قيمته في الصور أو السجلات.

## الحالة النهائية المعتمدة

- **المطلوب الأساسي للمدرب:** مكتمل.
- **التحقق المحلي للمطلوب الأساسي:** ناجح حسب النتائج المسجلة أعلاه.
- **تطوير HMAC الإضافي:** محفوظ في الفرع، لكنه غير مكتمل محليًا.
- **حذف التطويرات اللاحقة:** لم يحدث، ولا ينبغي حذفها لمجرد أنها ما زالت قيد التطوير.
