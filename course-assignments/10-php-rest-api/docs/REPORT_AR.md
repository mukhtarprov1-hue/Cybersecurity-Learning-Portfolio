# التقرير الفني — التكليف العاشر
## أداة معالجة طلبات HTTP وبناء Secure REST API باستخدام PHP

### 1. الهدف

تطوير واجهة REST API تعليمية تعالج طلبات HTTP الأساسية، وتستقبل بيانات JSON، وتتحقق من المدخلات، وتعيد استجابات منظمة بأكواد HTTP مناسبة. يركز المشروع على ربط مفاهيم بروتوكول HTTP بممارسات أمن تطبيقات الويب.

### 2. الوظائف الأساسية

- دعم GET وPOST وPUT وDELETE وOPTIONS.
- إنشاء الموارد وقراءتها وتحديثها وحذفها.
- تحليل جسم الطلب من php://input والتحقق من نوع المحتوى application/json.
- التحقق من الحقول المسموح بها وأنواع البيانات والترميز UTF-8.
- استخدام Bearer Token لحماية العمليات التي تغير الحالة.
- إصدار Request ID وربطه بالاستجابة وسجل التدقيق.
- معالجة أخطاء HTTP وإرجاع JSON منظم.
- تطبيق CORS allow-list ورؤوس الحماية.

### 3. التصميم المعماري

يفصل المشروع بين نقطة دخول HTTP، وطبقة معالجة الطلبات، ونموذج الاستجابة، ومستودع البيانات، وخدمة سجل التدقيق. تستخدم طبقة البيانات ملف JSON محلياً مع قفل للكتابة وملف مؤقت قبل الاستبدال لتقليل فرص تلف البيانات عند العمليات المتزامنة.

### 4. الضوابط الأمنية

- مقارنة Bearer Token باستخدام hash_equals().
- رفض عمليات الكتابة عند عدم إعداد API_TOKEN.
- حد أقصى لحجم جسم الطلب قدره 64 KiB.
- رفض JSON غير الصحيح والحقول غير المعروفة.
- التحقق من الطرق المسموح بها وإرجاع Allow عند HTTP 405.
- عدم تسجيل Authorization أو جسم الطلب في أحداث التدقيق.
- وضع ملفات التشغيل خارج public/.

### 5. نتائج التحقق من نسخة API الأساسية على Windows

- بيئة التشغيل: PHP 8.5.12 NTS x64.
- فحص تركيب ملفات PHP: 9 ملفات دون أخطاء.
- الاختبارات الأساسية: 23 ناجحة و0 فاشلة.
- GET Health: HTTP 200.
- POST Create: HTTP 201.
- GET Resource: HTTP 200.
- PUT Update: HTTP 200.
- DELETE Resource: HTTP 204.
- تجربة CRUD اكتملت بنجاح على عنوان loopback محلي.

### 6. تعزيز سلامة سجل التدقيق — فرع تطوير مستقل

أضيفت في فرع التطوير ميزة HMAC-Chained Audit Trail. يحمل كل سجل رقم تسلسل ورابط HMAC للسجل السابق، ويحسب HMAC-SHA256 على بيانات الحدث بترتيب حقول ثابت. تستخدم الميزة مفتاحاً مستقلاً من متغير البيئة AUDIT_HMAC_KEY، ولا تخزن المفتاح داخل المستودع أو سجل الأحداث.

أضيفت أداة مستقلة للتحقق tools/audit_verify.php واختبارات لمحاكاة تعديل سجل، وحذف حدث داخلي، وإعادة ترتيب السجلات، ومحاولة الإلحاق بسلسلة تالفة.

حالة هذه الإضافة في هذا التقرير: **قيد التحقق المحلي وCI**. لا تعتبر نتائجها معتمدة حتى تنجح اختبارات tests/audit_integrity.php على Windows وبيئات CI.

### 7. القيود المعروفة

- رمز Bearer مشترك لا يعادل نظام هوية أو صلاحيات متعدد المستخدمين.
- تخزين JSON المحلي ليس بديلاً عن قاعدة بيانات معاملية.
- سلسلة HMAC تكشف التغييرات وإعادة الترتيب والحذف الداخلي، لكنها لا تكشف حذف نهاية السجل دون نقطة تحقق مستقلة محفوظة خارج حدود ملف السجل.
- حماية السجل تعتمد على سرية مفتاح HMAC. اختراق المفتاح يتيح إنشاء سجلات صحيحة تشفيرياً.
- خادم PHP المدمج مخصص للتطوير المحلي وليس الإنتاج.

### 8. الخلاصة

يقدم المشروع تطبيقاً عملياً لمعالجة طلبات HTTP ومبادئ REST والتحقق الأمني من المدخلات والمصادقة والتدقيق. ويضيف فرع التطوير طبقة تحقق تشفيرية لسجلات التدقيق، مع توثيق صريح لحدود الحماية والافتراضات اللازمة.
